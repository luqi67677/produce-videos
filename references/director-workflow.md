# 从口播到导演分镜

## 先确定观众最后会明白什么

读完整稿，先写：这条片子给谁看；观众目前卡在哪里；看完能说明或做出什么；哪一个对象、问题或任务贯穿全片。写可检验的结果，例如“能区分派工返回与转交负责人”，不用“更加了解智能体”。

已批准文字逐字保留。若发现事实矛盾或口播明显超过目标时长，标出具体位置与修改建议；未获修改授权前不自行删句。视觉可以提前展示问题或结果，但不能创造原稿和证据没有的主张。

## 制作顺序

1. 导入原稿，写观众所得和贯穿线索。只盘点已有素材、声音和风格。
2. **先写全片导演分镜**，允许估时，允许暂缺素材。此时不生成新图，也不拼视频。
3. 校验原文覆盖与分镜完整性，展示可读分镜。已有授权直接复用，新选择集中处理。
4. **按镜头寻找与准备材料**。实景、照片、真实产品画面、静态补图与图解都有明确职责；核验来源、许可、画面质量和可用片段。
5. 使用已授权声音生成或读取正式旁白，按实际词句时间调整 EDL、字幕与画面事件。需要新声音时才试听选择。
6. 将素材与声音落实到原分镜，形成可合成的完整蓝图。新的实际素材若改变叙事，回到受影响镜头调整，不另起一份计划。
7. **最后制作各镜、合成样片、完整预览与母版**。样片只证明对应方法可用，最终仍需整片带声审看。

仅要求分镜时停在第 3 步。仅要求研究或升级 Skill 时不进入项目制作。

## 怎样把文字拆成画面

按意义切镜，不按句号、固定字数或固定三秒机械切。一个配音段可有多个镜头，每个镜头取其中一段连续原文；全部镜头拼回去仍是批准原稿。一镜一个主要观看任务，可以有支持它的多个元素。

先确定观看任务，再选载体：

| 这段需要观众理解什么 | 优先的画面组织 | 不合适的替代 |
|---|---|---|
| 真实环境、人物正在做什么、问题如何发生 | 实景视频，选择动作完整的片段；必要时局部标注 | 与句子无关的办公室或城市空镜 |
| 某产品怎么操作、输出是什么 | 实际产品截图、录屏或验证结果，围绕目标局部取景 | 用生成 UI 或其他产品画面当证据 |
| 人物、物件、场景关系 | 用户照片、合适素材或经授权生成的静态情境图 | 每隔三秒换照，脸部位置突然跳变 |
| 先后、依赖、分工、信息流 | 动态流程图，同一对象交接、状态逐步更新 | 一开始堆满所有箭头，靠字幕解释 |
| 层次、容器、共享与隔离、产品组成 | 必要时用 2.5D（二维模拟纵深）分层图，展开后逐层聚焦 | 为显得高级而旋转，遮住标签与连接 |
| 选择、对比、判断依据 | 同尺度对照、实际证据、结果停留 | 只有结论词或装饰性数据大字 |

这是选择方法，不要求每片平均分配素材类型。素材来源检查顺序也不等于每镜都先塞真实画面；抽象权限关系可以直接用图解。

## 每个镜头写到什么程度

逐镜写入同一 `shot-readiness.json`，字段说明见 `director-plan-contract.md`。

- **原文与估时**：准确引用；标明估时依据和合理阅读时间，不能把估时当测得的配音长度。
- **观众所得**：看完这一镜能说清什么。
- **画面组合**：主体、环境、支持元素、编号标题、字幕各放哪里；屏幕上先看哪一个，随后看哪一个。
- **素材需求**：需要哪个对象执行什么动作；来源路线、搜索词、可接受条件、找不到的替代方案。
- **运镜与动作**：景别、视线方向、推拉/横移/静止、开始和结束构图。物体怎么动，动作后什么改变。
- **交接**：上一镜保留什么，下一镜接住什么；连续对象保持锚点，硬切写明理由。
- **声音**：旁白沿用哪个来源；是否需要音乐；哪些事件加何种音效或环境声，何时开始、何时结束，为什么需要。无需音效就明确写无。
- **字幕**：由批准原文与最终旁白时间生成；短句自然分组，独立稳定，不跟随镜头缩放。标题编号、图中标签与字幕分工，避免同一句话堆三遍。

可读分镜用总览表加逐镜卡片，避免把十几栏塞进一张看不清的宽表。由 JSON 导出，修改原合同再重导，不手工维护两份。

## 运镜要带着观众看

镜头可以建立环境、看清动作、聚焦细节、展示结果。景别和方向的变化应服务这些步骤。2—4 秒是检查节奏的提醒；有相关实景动作或观众正在阅读结果时可以更长，不强制切镜。

照片可以用有目的的近景推进、不同局部、同一场景的另一动作或真实视频补足。换图先匹配脸部位置、眼睛高度、人物比例与视线；不要每次重新从不同的缩放起点弹出。同一照片缓慢放大不能包办整段讲解。

连续对象跨镜时，在 EDL 转场备注记录 `object_id`、出入位置、比例、透明度和运动方向；需要无缝运动时再核对速度。普通硬切不强制位置一致。检查切点前、后及转场中间，发现闪白、空帧、双影或突跳就修复。

出现“三种、第四种”等序号时，标题同步显示当前编号与名称。比较结束前保留前项或统一回到总览，使观众知道讲到了哪里。

## 让关系图讲清因果

需要空间结构时读 `spatial-mechanism-explainers.md`。先给物件定义：哪个代表角色，哪个是资料，哪个是本次任务状态，谁可读、谁可写。画面可以分层，概念不能因此被混为一层。

同一个 `event_id` 绑定口播词句、动作前状态、动作、完成状态和可选声音。资料确实到达后，接收者才能显示“已收到”。显示共享资料不代表每个成员共享全部对话；图中的连线也不能自动代表写权限。解释完局部，回到总览让观众看见它的位置。

立体遮挡影响中文或关系阅读时，回到平面。真实产品用实际证据，机制图标明示意；示意图不承诺真实后台实现。

## 声音帮助表达，留白也要设计

雨景可用与场景一致的雨声；资料抵达可用克制的一次落点声；章节改变可有短提示。讲判断标准、重要概念、引用原话时可只保留旁白。不能每出一条字幕、每动一根箭头就响一下。

每条声音写表达目的、触发、停止、尾音与是否允许叠加。先设计，再找对应合法素材；同一种音效不套所有事件。详细混音和实际听检见 `audio-system.md`。

## 自查与实际审片

合成前先从观众角度问：只看图能认出主对象吗？听到这句话时画面对应吗？这一镜比上一镜多讲清了什么？去掉某个动效或声音，会不会更容易理解？

完成后检查真实编码视频，分别记录：技术检查、连续带声审片、观众理解结果。不要由像素变化或字段齐全推断“讲清了”。用户审片通过只覆盖当次实际看到的版本和范围。

事实仍分为已证实、机制示意和待核验。所有数据记录单位、对象、条件与来源；通用实景只说明情境，不代替结果证据。
