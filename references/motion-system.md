# 流畅信息动画系统

## 目标

动画不是让静态页面“动一下”，而是让观众看见信息如何产生关系。每个镜头都要有起始状态、连续变化和稳定结束；画面顺序必须与口播的因果顺序一致。

## 时间模型

0. 先区分章节与镜头：章节是叙事分组，镜头是剪辑和运动单位。教程、工作流和录屏类内容默认每 2—4 秒更新一次有效视觉职责；连续操作可以超过 4 秒，但必须有可见状态推进，不能让一张章节页长时间代替演示。
1. 一条因果链只使用一条全局进度。主体出现后保持，连线从主体继续生长，下一节点再被激活。
2. 不让每个节点各自从零播放同一套进入动画，也不在节点完成后将它隐藏再重来。
3. 30fps 下，单个模块进入建议 15—30 帧，路径推进建议 18—36 帧，镜头结束至少保持 12 帧。
4. 默认使用高阻尼缓动或平滑三次曲线。回弹只用于有明确物理含义的物体，不能作为普通信息卡片的统一入场方式。
5. 一个元素通常只选择位移、遮罩、描边或透明度中的一到两种变化。禁止透明度、位移、缩放同时快速变化造成闪烁。
6. 背景、页眉、页脚、字幕安全区和水印默认固定；只让承担当前叙事职责的内容层运动。整页运动必须有明确转场含义，不能在每个镜头里重复缩放或漂移。
7. 列表、节点和卡片逐个出现后默认保持。消失只能表达替换、淘汰、离开或转场，不能为了“有动画”把已经建立的信息清空。
8. 动作时间由最终旁白线索驱动。先给镜头声明 `motion_grammar`，再为每个 `motion_step` 写出真实 `cue_text`、动作和是否保持；不要把 1、2、3 或五个步骤按镜头总时长机械平均。
9. 有效视觉必须覆盖到旁白结束。录屏、手机画面或素材卡先结束时，延续最后一个有效状态、自然循环可用段，或提前承接下一个相关视觉；不允许容器空着等声音念完。
10. 静态分镜决定正式镜头的稳定骨架。录屏只在分镜规定的主视觉窗口内播放；除非分镜明确批准 `raw-fullscreen`，不得从精排版式突然切成全屏原始录屏。
11. 每段录屏都必须绑定真实 `source_window` 和 `action_evidence`。同一素材再次出现时必须展示下一操作状态；循环、重播、换裁切或换彩框都不算状态推进。
12. 重点标注只在目标坐标附近短时出现，建议面积不超过画布 20%。标注前先在原生分辨率关键帧确认位置；整页边框、大面积矩形和与口播无关的框线不是语义动画。

## 按语义选择结构

| 内容关系 | 推荐动画 |
| --- | --- |
| 2月、4月、7月等事件 | 先画时间轴，再沿线依次点亮节点和事件卡 |
| 用户进入、聊天、剧情、任务、深度关系 | 一条连续路径按顺序生长，节点随路径抵达而出现 |
| 多个工具连接助手 | 中心角色先建立，连线依次向外生长，工具节点逐个接入 |
| 左右新旧对比 | 先建立旧状态，再用中轴或撕裂遮罩揭示新状态 |
| 多路信息汇成结论 | 两侧或多路先出现，连线向中心汇聚，最后点亮结论 |
| 卡片流程 | 横向流程、纵向阶梯、中心扩散、分区接力轮换使用 |
| 多张漫画或截图 | 按叙事顺序逐张替换或用分区遮罩揭示，不整页闪现 |
| 已批准的整张分镜 | 保持原图不重绘，用连续遮罩、描边和局部显现恢复顺序 |
| 口播指向按钮、字段或结果 | 目标区域保持稳定，用短时描边框、手绘圈、局部提亮或短箭头标出；口播结束后退出 |
| 原始录屏杂乱或有效动作太短 | 抽取可证明状态的关键帧，在已批准分镜中用遮罩、说明卡和局部指示建立关系；只有明确缺口才生成补图 |
| 没有、排除、不采用 | 使用叉号、划除或否定遮罩，不使用表示方向/跳转的箭头 |

同一条视频允许少量结构复用，但不能让所有非人物镜头都变成三张同尺寸色块平铺。

## 漫画与解释动画分工

- 完整漫画承担场景、人物关系和情绪，不把同一张漫画切成左右重叠页反复滑动。镜头需要变化时，优先让人物、道具、遮罩或视线方向完成一次短动作；除非用户明确要求，不默认使用缓慢局部聚焦或长时间 Ken Burns 推拉。
- 解释图承担逻辑展开。时间线、流程、网络、对比和任务链必须由口播触发，按“主体→关系→下一节点→结论”逐步出现。
- 漫画切换到解释图时，使用内容中的共同元素、同一方向或同一颜色做动作匹配；不用统一的左推右、叠页和闪白覆盖所有场景。
- 如果画面已经是一张完整且信息充分的漫画，宁可稳定阅读 2—3 秒，也不要为了“有动画”添加无意义晃动。

## 禁止模式

- 用 6—8 张章节板轮播来代替几十个真实操作镜头。
- 把“约 3 秒一次视觉更新”理解成整页每 3 秒晃一下、缩放一下或强行截断操作。
- 一开始就展示最终完整图，然后让整页晃动、缩放或扫光。
- 每个模块都使用同一个“弹出—抖一下—停住”动作。
- 用极短的透明度、位移和缩放叠加制造所谓节奏感。
- 前一节点完成后消失，下一节点又从空白重新开始。
- 列表逐项消失，镜头末尾只剩空白页。
- 局部元素已经出现后，再让完整页面二次淡入一次。
- 每个镜头都让整页轻微缩放、漂移或重新居中，造成全片持续抖动。
- 用箭头表达“没有、排除、不采用”，让否定语义看起来像跳转或引导。
- 用相同的三色卡片排列替代时间线、网络、对比和路径关系。
- 把已经确认的整张分镜切成无语义的条带碎片。
- 播放整段界面录屏却不标出当前正在讲的按钮、字段或结果，让观众自己寻找重点。
- 把语义标注固定挂满全片，或让圈选与口播错位、遮住原始文字和按钮。
- 给每段录屏自动套不同颜色的整页外框，再把这些框当作视觉主题或特效。
- 审核时展示精排静态分镜，渲染时完全丢弃该构图，只按章节随机播放原始素材。
- 为填满旁白反复播放同一段录屏，或只更换裁切、缩放和边框却没有新操作状态。
- 完整漫画之间统一套用重叠滑页、左右推拉或多层卡片交叠。

## 静态分镜到动画

第三次审查的静态分镜必须展示起始、变化和结束三个真实状态。渲染时逐项映射：

- 起始状态决定第一帧有哪些元素。
- 变化状态定义元素出现顺序、路径方向和时间窗口。
- 结束状态供观众阅读，不在完成瞬间立刻切走。

如果三张状态图无法说明“先发生什么、后发生什么”，先补运动设计，不进入正式渲染。

`shot-readiness.json` 还必须把每个镜头写成可执行运动契约：

- `motion_grammar`：本镜头采用哪一种关系结构。
- `motion_steps`：每一步对应哪句口播、执行什么动作、完成后是否保持。
- `focus_target`：口播具体指向哪个界面区域，使用哪一种标注、何时进入、何时退出；没有具体目标时明确写 `none`。
- `composition_source`：`storyboard` 或经过分镜明确批准的 `raw-fullscreen`；渲染器不得自行改变。
- `storyboard_state_ids`：本镜头实际消费的起始、变化和结束状态，不能只引用章节号。
- `source_window`：视频素材的真实入点、出点与动作证据。
- `decorative_outer_frame`：默认 `false`；为 `true` 时必须已经出现在被批准分镜中，并说明叙事职责。
- `visual_coverage_to_end`：最后一条旁白结束前是否始终有有效视觉。
- `blank_hold_seconds`：无职责空白累计时长，超过 0.5 秒不通过。

从 `assets/motion-plan-template.json` 建立运动计划。默认 `baseline_visible_from_start: true`：首帧先保留页眉、标题、主视觉或已批准的稳定骨架，再让当前口播承担的元素依次进入。不得为了“有动画”先把内容全部隐藏，造成观众看到空白底图后等待入场。确有停顿、转场或情绪留白时，必须记录 `intentional_blank_approved` 和叙事理由。

静态分镜只证明构图和关键状态，不能证明连续运动已经成立。`fast` 可用完整低清预览同时承担动态证明；`standard` 在蓝图通过后先做 4—8 秒代表性微样片；`high-risk`、首次运动语法或反复生成同一人物时，微样片还必须单独给用户确认。微样片只证明被抽中的运动语法，不能用一个局部动态片段替代全片逐镜运动证明。

完整预览还必须满足以下逐镜规则：

- 时长超过 1.2 秒的镜头，镜头内部至少发生一次由当前口播触发的语义变化；只有切入瞬间变化、静态图片持有、整页漂移、缩放、扫光或进度条变化不计入。
- 三项及以上列表、步骤、卡片、截图或流程节点必须按口播顺序分段建立；已出现内容默认保持，不能在下一项出现时消失。
- 切点必须落在词或短语结束后的自然边界；下一镜的标题、对象或结果不能提前替上一句旁白背书。
- 全片渲染后必须把预览、EDL、运动计划的文件哈希和逐镜检测结果写入机器审计；存在静态镜头、分段揭示失败、等待入场的空白或时间线漂移时，不得把完整预览登记为动态证据。

## Remotion 实现原则

- 因果链使用同一个 `frame` 派生各阶段进度，阶段窗口首尾相接。
- 路径优先使用 `strokeDasharray`/`strokeDashoffset`，节点在路径抵达后激活。
- 已批准的位图优先使用 `clip-path` 或遮罩连续揭示，不额外叠加整页淡入。
- 首帧直接存在，不让画面从黑场或透明状态开始。
- 转场以动作延续、遮罩推进和前后元素位置关系为主，不用通用闪白。

## 验证顺序

1. 静态分镜通过后先列出全片运动语法。`fast` 仅在语法成熟、无反复生成人物且无平台/隐私疑点时，直接用完整低清预览证明动作衔接。
2. `standard` 先制作 4—8 秒代表性微样片，必须消费最终声音、锁定分镜、真实主题、同一人物档案和平台安全区。机器与 Agent 检查通过后自动继续，不默认增加一次用户停顿；若暴露创意偏差、人物漂移或遮挡风险，再交给用户判断。
3. `high-risk`、首次运动语法或反复生成同一人物时，先把 4—8 秒微样片作为独立确认包给用户。若计划微样片超过预计成片的 40%，直接把完整低清预览作为本次动态证明和用户确认对象。
4. 样片或预览必须验证稳定页面骨架、真实主题底色、单层字幕、水印设置、平台 UI 遮挡、人物身份、素材结束承接和符号语义。所有模式最终仍要生成完整低清预览，并由用户批准后再导出正式母版，旧版本保留不覆盖。
5. 完整低清预览运行 `scripts/analyze_motion_coverage.py`，逐镜检查语义变化、分段揭示和画面占用；审计必须覆盖 EDL 全部镜头、绑定真实哈希，且没有静态镜头、分段揭示失败、空白镜头或时间线漂移。
6. 执行类型检查和成片预检，确认画幅、时长、声音和黑帧。
7. 打开 24 帧联系表检查全片结构，再逐帧抽查复杂动画的开始、中间和结束。
8. 人工完整观看，重点检查异常闪切、元素退回、整页二次淡入、人物漂移、平台遮挡和停留不足。
