# 质量门

## 阶段门

| 阶段 | 必须通过 | 未通过时 |
|---|---|---|
| 口播 | 事实、禁用词、时长、完整文本、真实 0—2 秒开场证据和叙事契约 | 不盘点素材、不做风格和渲染 |
| 用户真实素材 | 实际文件、来源、授权、用途、隐私目标、联系表和明确审批；无素材也要确认 | 不推荐风格、不生成镜头素材 |
| 主题候选 | 34 模板完整目录、三套不同主题、真实封面/内容/缩略图样张、逐项质量复核与视觉干净度硬门 | 不向用户展示候选、不锁定主题 |
| 音频产物 | 成品音频，或 API/本地模型预检、用户选声、实际音频文件、SHA-256、时长、采样率、声道和连续时间戳 | 不做字幕、镜头和全片渲染 |
| 镜头素材 | 来源、授权、用途、缺口、原始素材审片计划、全部素材联系表、复用矩阵、人物档案、独立封面草图和明确审批 | 不排静态分镜 |
| 静态分镜 | V2.6 全量剪辑镜头、逐句口播、真实审查帧、证据、版式、观众文案边界、场景化人物动作和平台遮挡审查 | 不做全片动画 |
| 动态证据 | 完整低清预览及逐镜运动审计；`standard/high-risk` 另含代表性微样片；覆盖语义切点、适量动画、无等待入场空白、人物一致性和平台安全区 | 不导出正式母版 |
| 独立封面 | 主标题、副标题、Skill 名称、主题绑定、主视觉动作、服装语境、原尺寸和缩略图 | 不交付封面 |

这些是机器阶段，不等于五次用户停顿。内容方向包可同时批准口播与真实素材，成片蓝图包可同时批准镜头素材与分镜。每条阶段记录仍必须证明审查产物已经直接展示；HTML 不能替代图片，播放器页面不能替代可播放视频，动态证据必须附联系表。新项目使用 V2 审批账本。

## 自动检查

- `validate_video_theme.py`：唯一主题、模板来源、颜色对比度，以及无地面、无投射阴影、克制轮廓光的视觉干净度契约。
- `validate_master_script.py`：完整口播段落、全篇逻辑和可提交用户审查状态。
- `validate_theme_catalog.py`：34 套模板与索引一一对应，每套预览和设计规范完整并包含 CJK 与已知限制。
- `validate_layout_catalog.py`：88 套布局规格与预览一一对应，并包含使用条件、结构、适配和限制。
- `validate_style_options.py`：验证 34 套模板逐项评分，再确认三套候选来自完整目录，具有真实 3:4 封面、目标画幅内容帧、信息流缩略图和逐项质量复核；V1.3 起还强制登记单一焦点、无地面、无投射阴影、轮廓光控制、截图重构和字幕视觉重量。候选展示时可只要求素材机器校验，用户选定后 `--require-selected` 同时强制验证真实素材批准。
- `validate_source_assets.py`：验证用户真实素材文件、哈希、来源授权、用途、隐私处理和联系表；无真实素材时要求记录原因。
- `validate_narration_contract.py`：音色来源、发音映射、单层字幕、时间戳。
- `discover_audio_models.py`：只扫描标准缓存和用户指定目录，并有限发现可导入 `mlx_audio` 的现有 Python 运行环境；默认解释器失败不能直接判定缺少依赖。
- `model_preflight.py`：使用发现报告选定的 Python 检查设备、运行时、依赖、模型目录和最小加载，并把实际解释器写入报告。
- `validate_voice_brief.py`：确认 Agent 已在开工信息包中询问并记录用户想要的性别呈现、年龄感、气质、能量、语速和禁忌特征；未获用户确认不得生成试听，后续不得重复追问已锁定字段。
- `validate_voice_selection.py`：本地模型绑定发现与预检，TTS API 绑定无密钥预检；两路都验证同文案试听、最终声音和用户批准。
- `prepare_qwen_model.py`：读取单一模型配置；只有明确授权参数同时存在时才下载。
- `register_audio_artifact.py`：登记用户已有音频或其他 TTS 的实际产物信息。
- `validate_shot_readiness.py`：素材、分镜帧、补图必须真实存在；同时检查授权、禁用词、安全区、版式复核、隐私目标、人物动作、镜头复用和既有成片修改范围。V2.6 还逐一校验剪辑镜头的批准口播、语义边界、真实审查帧、证据完整度、观众文案边界、孤行、品牌大小写、画面密度、人物动作签名与服装语境；未知 schema 直接失败。
- `validate_timeline_sync.py`：校验 V2.6 逐镜表、V1.1 EDL 和批准旁白使用同一组镜头 ID、顺序、文字、时长、A/B-roll 职责与已听审语义切点；任何串页、空洞或重叠都停止渲染。
- `validate_creative_foundation.py`：校验叙事契约、原始素材审片路由、项目/工作区记忆授权、平台安全区目录和人物身份档案。
- `analyze_motion_coverage.py`：读取完整低清预览、V1.1 EDL 和运动计划，按镜头统计有效视觉变化、最长静止段和欠填充停留，识别静态镜头、未分段建立、等待入场空白和时间线漂移，并绑定三个文件的 SHA-256。
- `validate_motion_coverage.py`：运动语法覆盖，并用 `ffprobe` 确认微样片与完整预览真实存在、包含视频流和有效时长；V1.4 契约强制逐镜运动审计覆盖完整 EDL、哈希未漂移、无静态镜头、分段揭示失败、空白镜头和同步失败。
- `validate_cover_contract.py`：校验独立封面的 3:4 输出、主副标题分工、Skill 名称大小写、主题哈希、主视觉动作与服装语境、原尺寸和缩略图用户审查。
- `validate_review_approval.py`：读取 V2 单一审批账本或旧版独立文件，校验阶段、确认包、文件哈希以及审批是否覆盖本阶段实际文件。
- `validate_render_gate.py`：预览渲染要求口播、真实素材、镜头素材和分镜四项审批；正式母版额外要求动态证据审批。渲染入口必须用 `--narration-contract` 传入实际旁白契约，并重新校验真实素材、完整 34 模板目录、主题、旁白、镜头和动态覆盖。
- `video_preflight.py`：画幅、时长、编码、音轨、响度、黑帧、静音、联系表，并在指定契约时校验旁白文件绑定；响度超出 -19 至 -14 LUFS 或真峰值高于 -1.0 dBFS 时失败。
- `scan_release.py`：发布 Skill 前扫描个人标识和本机路径。
- `doctor.py`：只读报告 Python、FFmpeg、Node、中文字体、本地 STT、TTS API 名称和本地 Qwen，不安装、不下载、不显示密钥值。
- `resume_project.py`：只从既有审批账本和已审批文件哈希推导进度，不写入第二套状态。
- `transcribe_media.py`：用本地优先 STT 输出可缓存词级时间戳；未显式授权时不下载模型。
- `build_beat_grid.py` / `snap_edl_to_beats.py`：建立节拍网格并只吸附安全切点，不切词、不改变总时长。
- `export_fcpxml.py`：从同一 EDL 输出 FCPXML 1.10；导入剪辑软件后仍需人工验证兼容性和扁平化边界。
- `package_release.py`：生成通用 `.skill/.zip`、WorkBuddy ZIP 和 SHA-256 清单。

## 必须生成的证据

1. 锁定画幅、内容模式、目标时长、硬上限和平台安全区配置。
2. `story-contract.json`：0—2 秒可见证据、唯一核心张力、贯穿线和结尾兑现。
3. 完整 34 模板目录检查结果，以及三套真实样张检查结果。
4. 用户真实素材清单、联系表、`asset-review-plan.json`，以及需要 TTS 时的 API/模型预检、声音选择和用户批准记录。
5. 需要反复人物时的 `character-profile-*.json`、身份锚点与跨 A/B-roll/封面/补图的一致性检查；启用记忆时的 `creator-memory.json` 与授权绑定。
6. V2 审批账本中的五条机器阶段记录及其实际文件 SHA-256；旧项目可保留五份独立文件。口播阶段绑定母稿和叙事契约，旁白契约再反向绑定同一母稿。
7. V2.6 逐镜表、V1.1 EDL、平台 UI 遮挡审查图、微样片/完整低清预览契约、V1.1 逐镜运动审计、FFprobe 规格、响度、黑帧、静音、24 帧联系表和成片 SHA-256。
8. `cover-contract.json`、1080×1440 独立封面及 270×360 信息流缩略图。

## 人工检查

- 事实是否有证据，推断是否被标记；
- 0—2 秒是否已经让观众看见结果、反差、真实冲突、问题或演示证据；冲突是否来自素材而非人为编造；
- 全片是否只围绕一条核心张力推进，每个镜头是否改变信息状态，结尾是否兑现开头承诺；
- 私人信息和未授权素材是否出现；
- 地址栏、书签、头像、账号、微信 ID、本地路径、通知内容、手机状态栏中的录屏红点、录制胶囊或录制计时，以及侧边栏中的仓库名、栏目名、项目名、草稿标题和文件树，是否已安全裁切或使用不透明马赛克；轻度模糊不得判定为通过；
- 同一录屏在开头预告、正文和结尾回顾中的全部复用镜头是否使用了同一隐私遮挡；只修用户指出的一帧不得判定为通过；
- 标题、字幕、数据是否在目标设备可读；
- 主标题是否在最终字体加载后按真实容器宽度测量；多行标题是否不存在只剩一至两个汉字、字母或数字的孤行，且没有用删词或改写掩盖排版问题；
- 34 套模板是否全部在索引中；三套候选是否确实从全库按内容筛选，而非固定组合；每套真实样张是否都达到可展示质量；
- 生成与合成画面是否出现地面、地平线、底座、地面反射、投射阴影、悬浮阴影或长阴影；出现即失败，除非用户明确要求真实空间且审批记录完整；
- 主体需要分离时是否只使用一侧柔和、低饱和的轮廓光；霓虹描边、完整光环、硬白边或发光毛边均判定失败；
- 是否叠加多套色偏、渐变、纹理、阴影或重色字幕条；是否把整页截图缩小塞入卡片，或残留原图箭头、标题、边框和半个物体；任一项造成素材拼贴感均判定失败；
- 人物、Logo、截图是否被错误裁切或遮挡；
- 平台遮挡审查图是否覆盖顶部导航、右侧交互和底部账号/文案区；主标题、首屏结果、字幕、人物面部和交互目标是否全部避开，且遮挡层没有混入成片；
- 动画是否与旁白同步并推进信息；
- 每个切点是否在当前词组、句子或操作结果结束后；是否存在上一句旁白跑到下一画幅，或下一镜提前替上一句背书；
- 每个时长超过 1.2 秒的镜头内部是否至少有一次由当前口播触发的语义变化；只有切入、进度条、整页漂移、缩放或扫光不得判定为通过；
- 三项及以上列表、步骤、卡片、截图或流程节点是否按口播顺序分段出现并保持；整页一次性出现后静止停留不得判定为通过；
- 每镜第一帧是否已有稳定骨架或主视觉；是否为了等待元素入场先出现大面积空白，连续欠填充超过 0.2 秒即失败，除非有经审查的叙事理由；
- A-roll 是否持续提供叙事或人格/对象主轴；B-roll 是否准确说明 `covers`，提供真实证据、操作或必要图解，而不是装饰性切走；
- B-roll 切入和返回后声音主轴与总时长是否不变；转场是否保留了对象、动作、方向、形状或因果中的至少一个连续性锚点；
- 每个镜头是否只有一个第一焦点、同一材质系统和有限的辅助组；大面积空白是否有可说明的构图职责，而不是主体过小或横版整体缩进竖版；
- 开始、信息变化峰值和结束三帧是否都像完成稿；是否存在只有动画运动时才被遮掩的孤立图形、脏边或裁切残留；
- “已保存、已同步、已进入草稿箱”等完成态口播是否有对应动作或结果证据，而不是只出现设置页或预览页；
- “分镜、短样片、导出、布局数量”等能力口播是否展示真实预览、关键帧或足量代表样本；空框、编号占位或只写能力名称均判定为失败；
- 多步骤片尾是否保留全流程可读，并让当前节点、连接或进度随口播逐项推进；一次性全部出现后静止停留判定为失败；
- 口播中的“第几步”是否在对应镜头持续显示当前编号、总步骤和流程位置；只在声音中报数判定为失败；
- 同一片尾构图是否连续停留超过 6 秒；长回顾是否至少切换两种构图，并在用户要求时提供独立行动引导；
- 主素材只占一侧时，负空间是否有与内容发生关系的步骤卡、箭头或已授权角色；纯装饰贴图和遮挡证据均判定为失败；
- 每个角色是否有明确接触对象、叙事动词和可见结果；同一站姿或指向姿势跨建库、同步、Skill、输出等不同语义重复出现，或只做上下浮动，均判定为失败；
- 同一 `character_id` 在 A-roll、B-roll、封面、补图和代表性样片中是否保持脸型、发型、体型、服装、色板和画风；未经说明的换脸、换衣或画风漂移直接失败；
- 每个含人物镜头的动作和服装是否符合当前场景；重复姿势、只做镜像/位移、促销式手势或任意跪坐是否已经被阻止；
- 创作记忆是否只复用用户明确批准为 `active` 的规则；单次反馈不得自动升级为长期偏好，项目进度仍只能由审批账本推导；
- “官方/第三方”“预览/同步/发布”等产品属性是否有官方帮助、官方仓库或插件目录证据；凭印象定性判定为失败；
- 动态样片、完整低清预览和成片关键帧是否与已批准静态分镜保持同一构图骨架；若分镜是精排版式而成片变成原始录屏轮播，直接失败；
- 局部修改是否先锁定基线和受影响镜头、逐条解决反馈并确认局部预览；未确认预览就整片重渲染，或误改保留镜头，直接失败；
- 录屏是否使用分镜记录的真实入点、出点和操作状态；循环、重播、随机裁切、换边框不算新镜头；
- 是否存在未经分镜批准的整页彩色外框；重点标注是否落在正确目标附近、面积不超过约 20%、随口播及时退出；
- 录屏动作杂乱时是否改用已批准关键帧或补图，而不是强行播放无关移动；
- 片尾是否自然结束，不留空白或突然断音。
- 独立封面是否为 3:4 原生重构；主标题是否说明目标用户/场景与痛点或结果，副标题是否说明 Skill 差异，Skill 名称是否明显且大小写正确，人物动作是否服务标题；横屏首帧裁切不能代替封面。
- 成片是否使用 3:4 竖屏或 16:9 横屏；9:16 旧规格不得误判为当前 portrait 通过。
- Qwen 正式旁白是否使用用户已确认的声音描述或试听候选；模型下载成功但未选声不能通过。

自动检查不能替代真实平台发布或真实用户反馈。
