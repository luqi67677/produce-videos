# 创作记忆与人物一致性

## 记忆不是第二套进度

`approval-ledger.json` 仍是当前项目进度的唯一真实来源。`creator-memory.json` 只保存用户明确希望跨视频复用的创作偏好、已验证视觉语言和退役规则，不记录“做到哪一步”。

## 存储边界

- 默认只在当前视频项目生成 `creator-memory.json`。
- 需要跨项目复用时，由用户指定一个 Skill 目录之外的工作区路径并明确授权；Agent 不全盘搜索历史项目。
- 不把图片、声音、水印、API 密钥或私人绝对路径写回 Skill。
- 记忆中优先保存规则、内容摘要和 SHA-256；只有用户授权时才保存工作区内的相对引用。

## 什么可以记住

每条记忆只能处于 `candidate`、`active` 或 `retired`：

- 用户明确说“以后也这样”时，可直接记为 `active`。
- 用户只批准一条成片，默认只是本项目通过，不自动上升为永久规则。
- 未获明确长期授权的偏好，至少经过 3 个可比项目的通过证据，才能从 `candidate` 建议为 `active`，仍需用户确认。
- 用户否定过的语言进入 `retired`，新项目不得再默默使用。

新项目开始时，只回显与本次任务相关的少量 `active` 规则，标记“继续使用”“本次实验”或“不再使用”。与当前明确需求冲突时，当前需求优先。

## 人物锁定

只要同一个真人、品牌角色或生成人物会在两个以上镜头出现，就从 `assets/character-profile-template.json` 建立项目内人物档案。

锁定顺序：

1. 记录角色 ID、授权和参考素材 SHA-256。
2. 用用户的话记录必须保持的身份特征：年龄感、脸部、发型、服装、色彩、身形、画风、使用场景和禁止变化。
3. 用户已提供并明确采用的原图可直接作为身份锚点，记录原始批准语句；不再重复生成或询问同一身份。只有需要新人物时才生成新身份锚点；已有批准原图继续复用。新身体表演仍需两个代表动作，并检查换脸、换衣、画风与服装语境。固定原图讲解模式的身体多动作检查标记为不适用，不能伪填已审。
4. 新生成身份样张作为高风险原始素材单独确认；用户已指定的原图复用原批准记录。新增姿态、表情或改衣仍需要相应授权；原图批准不等于后续分镜或动态样片批准。
5. A-roll、B-roll、封面和静态补图共用同一档案。镜头只能改变已允许的表情、姿势和道具，不能重新设计身份。

用户未定义人物时，Agent 可帮助整理候选定义，但在用户锁定前不得批量生图。

## 固定原图讲解人与表演角色

仅用户选择静态原图讲解人时，采用 `presentation.mode=static-presenter`、`body_motion=fixed`、`animated_regions=[]`、`mouth_behavior=non-speaking`、`mouth_driver=null`。嘴、眼睛和身体完全静止，人物按职责辅助主画面，主画面按题材选真实素材、物件或必要图解。人物旁可添加独立的小喇叭和轻微声波提示旁白，不冒充口型或人物动作。当次明确要求覆盖旧长期行为配置，原身份与声音继续复用；历史动作与口眼设置不自动恢复。

`generated-performance` 只在用户明确选择人物表演时采用。旁白配轻微动作可使用 `performance_style=subtle-presenter`；小幅头部或手势须来自真实动作素材，嘴保持非讲话表情。新动作样段待制作时各效果复核为 false，不把静图摇晃称为身体表演，不挪用旧口眼效果批准。

旧口眼模式仅在用户明确选用时采用。`presentation.mode=audio-driven-presenter` 表示身体和站姿保持原图，嘴随真实配音开合，眼睛自然眨动。用户要求以后调用也这样时，身份、口眼授权和局部素材保存在 Skill 外的本机默认人物配置，不再每次选人或重问嘴眼是否允许动。音量模式明确 `lip_sync=false`，不能称为逐字音素同步；不顺带加入点头、挥手、呼吸或新姿态。

用户选择 `static-presenter` 时直接复用已批准原图，不要求生成人物动作或嘴眼试样。两种固定原图模式都可以按讲解职责复用全身、半身或面部裁切；出场和淡出只是合成，不能宣称角色抬手、转身或操作。身体代表动作和动作轮廓去重保持 false，在 `presentation.review_not_applicable` 说明无身体表演。仍检查身份、服装语境、解剖安全与实际素材 SHA。

动态模式另外绑定真实配音、局部嘴眼源素材、短样视频及 `presentation.motion_review`；技术复核与用户审片分开，原图采用批准不替代新效果批准。详见 `ip-presenter-directing.md`。

以下动作去重要求适用于 `generated-performance` 或实际身体表演素材，不套用到固定原图讲解人。

## 动作不是身份锚点

同一人物需要保持“是谁”，不需要保持“每页都做同一个动作”。每个含人物镜头先写清 `action` 和 `action_signature`：人物对哪个对象做什么、让什么信息发生变化。讲解、递交、指向、确认、操作、收束和行动引导应有不同的动作轮廓。

- 只改左右位置、镜像、缩放、手里卡片或背景，不算新动作。
- 动作、表情、道具和服装要服务当前 `visual_duty`；像促销、站台或夜场展示的手势不能替代职业讲解。
- 重复动作只有在连续动作接力或明确回环时才允许，并在逐镜契约中写 `reuse_reason` 后人工复核。
- 批量生图前检查动作签名去重；代表动作未复核、服装语境未复核或动作轮廓重复时，不得锁定人物档案。
- 封面人物遵守同一身份档案。表演模式按标题设计动作；静态模式可复用原姿态，用景别、裁切和标题位置组织封面，不强制生成人物动作。两种模式均不能随意跪坐或摆拍。

## 原始素材快慢分流

从 `assets/asset-review-plan-template.json` 建立 `asset-review-plan.json`：

- `merged-blueprint`：低风险素材先做机器检查和原图联系表，再与完整静态分镜放在同一确认包，不增加一次用户停顿。
- `risk-first`：反复生成的人物、品牌身份、隐私录屏、授权不确定素材、容易被误认为真实证据的生成图，先展示原图和身份锚点，确认后再批量排分镜。

风险分流改变的是“用户在哪里看”，不是“机器要不要检查”。两种模式都必须有原始素材联系表、来源、授权、隐私和实际文件哈希。
