# 版式与安全区

版式不是把内容塞进模板。34 套主题只负责视觉语言；88 套 `references/frontend-slides-layouts/` 负责构图骨架。当前内容的主次、断行、主视觉大小和观看距离仍必须重新设计，并把选择写入 `shot-readiness.json.layout_preset`。

## 结构选择

- 先按镜头职责选择 slot：opening、video、image、list、stats、chart、comparison、timeline、process、quote、closing 等。
- 再读取该布局的 Geometry、Content constraints 和 Failure modes；不能只看名字或预览图。
- 横屏使用原生 1920×1080 骨架；3:4 竖屏保留层级和比例关系后重新排区，记录 `portrait-reflow`，不能整体缩小。
- 每个镜头填写 `composition_budget`；详细阈值和脏画面禁令见 `references/visual-cleanliness-system.md`。
- 结构化分隔线可以用于编辑排版，但不得被画成承托主体的透视地平线或地面。

## 画幅

- 横屏：1920×1080，16:9。
- 竖屏：1080×1440，3:4。
- 样张、生图、静态分镜、动态样片和成片必须使用同一目标画幅。

### 横屏 16:9

- 左右安全边距至少 120 px，顶部至少 72 px；需要字幕时，底部预留约 180 px。
- 适合左右并列、证据加结论、流程和时间线，但一镜仍只承担一个主要信息职责。
- 不把竖屏内容居中后补背景，也不把整页 PPT 缩小塞入画面。

### 竖屏 3:4

- 左右安全边距至少 64 px，顶部重要内容从约 144 px 以下开始；需要字幕时，底部预留约 240 px。
- 一屏保留一个主视觉动作；横向流程改为纵向递进，不把整条流程等比缩小。
- 主体高度优先占画面 42%—62%，避免中央只有一个小物体、四周全是空背景。

## 平台 UI 遮挡审查

- 从 `assets/platform-overlay-profiles.json` 读取平台配置。未匹配到具体平台时使用通用画幅配置，不凭印象发明安全区。
- 抖音 3:4 竖屏默认只采用保守审查值：顶部 12%、底部 24%、右侧 16%。这些值不是平台官方规范；用户提供近期截图时，在当前项目保存校准覆盖值，内置目录保持不变。
- 竖屏分镜生成一张可关闭的 UI 遮挡审查图，至少模拟顶部导航、右侧交互按钮、底部账号/文案/搜索区。遮挡层只用于审片，不进入最终视频。
- 主标题、首屏结果、字幕、按钮、关键数据、人物面部与交互目标不得落入遮挡区；关闭遮挡层后，画面本身仍须构图成立，不能依赖半透明蒙层掩盖脏边或空白。
- 若平台界面已改版又没有近期截图，明确标记“使用保守预设、待真机复核”，不得把预设描述成当前官方尺寸。

建立 `shot-readiness.json` 后，可生成实际审查层：

```bash
python3 scripts/generate_platform_overlay.py project/shot-readiness.json \
  --output project/storyboard/platform-overlay-review.svg
```

将输出路径写回 `platform_overlay.review_overlay_path`，再把审查层叠在完整分镜总览上直接展示给用户。

## 中文与品牌名

- 中文或中英混排标题使用中文优先字体栈：`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`、系统无衬线。
- 展示字体只用于数字、短英文眉题或纯英文装饰；不得把全大写展示字体直接用于含中文或品牌名的主标题。
- 品牌名、产品名和插件名按原稿建立精确 token，例如 `Obsidian`、`Web Clipper`、`Wechat Converter`；不得改写大小写或拼写。
- 禁止在主标题层使用 `text-transform: uppercase`。如模板需要全大写效果，只能用于不承载品牌名的英文装饰层。
- 用户确认过的标题必须逐字保留，排版只能调整字号、语义断行和位置；不得删词、改写、换标点或改数字。标题允许行数由当前 brief 根据画幅和标题长度确定。
- 只有用户明确确认独立封面标题时，才能区分内容标题与封面展示标题；没有这项确认时，两者必须完全一致。

## 封面信息密度

- 封面只保留：一个主标题、一个主视觉、一条辅助信息。必要的账号标识另行占位，不参与标题竞争。
- 标题较长时，先通过字号、语义断行、标题区宽度和主视觉比例解决；不能擅自缩短标题。日期、页码、模板名、镜头编号和内部说明仍应删除。
- 有真实截图、产品界面、人物或证据时，选一个作为唯一主视觉；除非明确选择纯文字封面，主视觉建议占可用舞台 42%—62%。
- 主标题和主视觉必须形成清楚的左右、上下或前后关系，不能分别缩在两个角落，中间留下无意义的大空白。
- 缩到常见信息流尺寸后，应在一秒内读出标题，并看清主视觉是什么。

## 稳定骨架

- 背景、页眉、页脚和安全区默认稳定。
- 标题、数据、截图和卡片在网格中对齐。
- 变化发生在承担语义的信息层，不通过整页持续漂移制造“动态”。
- 封面、内容页和结尾可以共享主题 token，但不能机械共享同一构图；每一类画面有自己的信息职责。

## 主体分离与景深

- 生成主体和产品合成默认悬置在纯色、轻材质或透明背景中，不建立地面、地平线、底座和地面反射。
- 不使用 `box-shadow`、投射阴影、悬浮阴影或长阴影制造层次；真实素材自带的自然阴影可以保留，但不再叠加第二层阴影。
- 主体与背景接近时，优先调整明度、色相和留白；仍需分离时，只增加一侧柔和、低饱和、窄范围的轮廓光。
- 轮廓光只描出必要边缘，不能包围整个主体，不能呈现霓虹色、硬白边或发光毛边。
- 用户明确要求真实桌面、房间、街道等空间时才允许地面例外，并在主题契约和样张审批中留下记录。

## 可读性

- 主文字与背景对比度至少 4.5:1。
- 反白大字与强调色对比度至少 3:1。
- 字幕容器按实际行数占高，不固定切出大块底栏；默认不用高饱和深色通栏，避免字幕成为第二主视觉。
- 真实设备缩略图检查标题、字幕、按钮和关键数据。
- 先检查 1920×1080 或 1080×1440 原图，再检查约 270×360 的信息流缩略图；两者缺一不可。
- 原图检查裁切、对齐、字体、截图清晰度和空白；缩略图检查标题识别、品牌大小写和主视觉辨识度。

## 水印

默认关闭。只有用户提供并授权水印时启用，位置必须避开字幕、人物、平台控件和重要证据。水印设置写入 `shot-readiness.json`，全片统一读取。

## 人物和角色

人物不是必选装饰。只有镜头确有叙事职责并且素材已授权时才使用；必须检查肢体、接触点、遮挡、边缘裁切和透明通道。

- 当真实界面集中在画面一侧、另一侧形成大面积负空间时，可以使用已授权人物或拟人化产品角色补足构图，但角色必须指向步骤、承接箭头、提示重点或完成转场。
- 同一角色在连续镜头中必须改变叙事动词、接触对象或可见结果，仅改变位置、缩放、左右镜像或上下浮动不算新动作；把相同贴图固定粘在角落不算动态设计。
- 角色出现前先写“谁对什么做什么，让什么发生变化”。手机同步应由与该助手身份相关的人物触发手机到电脑的传递，Skill 沉淀应出现电脑输入或整理动作，闭环应出现推动、连接或接力；写不出因果链就不放角色。
- 角色不得遮挡操作证据、字幕、步骤编号和隐私遮挡，也不得代替缺失的真实产品结果。

## 真实界面隐私

- 浏览器地址栏、书签栏、头像、账号、微信 ID、本地私人路径、通知内容、未授权联系人，手机状态栏中的录屏红点、录制胶囊或录制计时，以及侧边栏中的仓库名、栏目名、项目名、草稿标题和文件树，默认视为隐私区或界面残留检查项。
- 优先安全裁切；无法裁切时使用不透明马赛克或完全遮挡。轻度模糊仍可能还原文字，不算通过。
- 安全裁切后必须复查讲解对象是否仍完整、可读、构图是否失衡。若裁切会切掉正在讲解的 Skill 列表、按钮或结果，改为只遮目标所在的最小行；账号后台可裁掉地址栏、头像和导航，并放大正文或草稿结果区。
- 同一素材在封面、静态分镜、动态样片和成片中必须复用同一组遮挡坐标，不能只给封面打码。
- 隐私检查以“素材的全部出现位置”为单位；用户指出一处泄露时，要回查这段素材在开头预告、正文、结尾回顾中的所有复用镜头。
- 遮挡完成后按原尺寸逐帧抽检，再检查缩略图；边缘不能因缩放、运动或转场短暂露出。
