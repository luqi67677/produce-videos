# 资料到镜头级动态视频编排

## 输出边界

输入可以是文档、讲稿、PPT/PDF、截图、图片或录屏；它们只是事实和素材来源，不直接等于视频画面。PPT/PDF 只提取标题、图表、图片和结构，不整页静态播放。

完整制作至少产生：`video-brief.md`、`claims-ledger.md`、`master-script.json` 及审批、用户真实素材清单与审批、API/本地模型预检及声音选择（需要 TTS 时）、唯一主题、整批镜头素材与审批、镜头就绪表、全量静态分镜、动态样片与审批、正式旁白、单层字幕、成片、独立 3:4 封面、QA 报告和联系表。

## 画幅与时长

- `portrait`：3:4、1080×1440、30fps。
- `landscape`：16:9、1920×1080、30fps。
- 账号短视频默认 25—75 秒，非必要不超过 90 秒；通用宣传视频默认 90—150 秒，硬上限 180 秒。
- 超过上限时压缩主线或拆成多条，不提高到不自然语速，也不切掉换气和字头。
- 每条成片另交付 1080×1440 独立封面，横屏视频也按 3:4 重新构图。

## 责任链

| 阶段 | 输入 | 可核验输出 | 下一阶段条件 |
|---|---|---|---|
| 事实与口播 | 原始资料、平台与受众 | 主张账本、完整口播、风险词清单 | 用户确认完整口播 |
| 用户真实素材 | 用户提供的录屏、截图、照片、品牌与官方资料 | 实际文件清单、授权、隐私目标、联系表 | 用户明确确认；没有素材也要确认 |
| 主题 | 稳定口播、已批准真实素材、真实标题 | 从 34 套中筛选的三套同内容样张或用户指定主题 | 用户只选择一次 |
| 音频准备 | 口播、成品音频、TTS API 或本地模型 | API/模型预检、三份试听、声音选择、旁白契约 | 来源和声音均已确认 |
| 镜头素材 | 已批准真实素材、主题、口播与素材缺口 | 整批素材清单、联系表、复用矩阵、封面草图 | 全部素材明确批准 |
| 静态分镜 | 已批准素材、最终旁白段落 | 原尺寸逐镜帧、镜头就绪表、口播一对一映射 | 全量分镜明确批准 |
| 动态样片 | 已批准分镜、正式声音与字幕 | 覆盖所有运动语法的最短真实样片 | 全部样片明确批准 |
| 成片与封面 | 五项有效审批、同一主题与时间轴 | 可播放视频、独立封面、QA 与 SHA-256 | 技术检查和人工检查均通过 |

## 口播与镜头

1. 先写一句核心价值，只保留支撑它的事实、步骤和证据。
2. 工具类内容按“准确身份与用途 → 使用方法 → 结果证据”展开；完成态不能由设置页或预览页代替。
3. 每个旁白段只绑定一个镜头，每个镜头只增加一种信息职责。
4. 默认每 2—4 秒出现一次有效视觉变化；连续真实操作可延长，但必须持续推进状态。
5. 最终旁白生成后回填实测时长和分段时间戳；声音变化后重新对齐字幕、镜头、样片和成片。

## 五次审查

1. `script`：一次性展示并审批独立 `master-script.json`。旁白契约必须逐段绑定它；任何 `display_text` 变化都会使本阶段及下游审批失效，音频技术字段变化不会误伤口播审批。
2. `source-assets`：在风格与分镜前展示用户真实素材、来源授权、隐私处理和联系表；没有真实素材也要明确确认生成边界。
3. `assets`：展示整批镜头素材、清单、联系表、复用矩阵和封面草图；只审批文字清单不能通过。
4. `storyboard`：展示真实目标画幅的全部分镜帧、镜头状态、视觉证据和安全区；抽检不能代替全量检查。
5. `motion`：使用最终声音、字幕和真实素材，为全片每种运动语法制作最短可证明样片。

任何确认都只证明当前阶段。上游事实、素材、声音、时间轴或构图发生变化时，只保留不受影响的审批，并重新展示受影响产物。

## 成片质量

- 成片必须继承已批准分镜的构图骨架，不把精排分镜换成原始录屏轮播。
- 平台风险词和禁用词覆盖口播、字幕、画面文字、封面和发布文案。
- 人物、Logo、产品截图和完成结果必须语义正确；真实证据可用时不用近似生成图替代。
- 完整联系表按原生分辨率检查事实、隐私、空白、裁切、字幕、人物动作、镜头连续性和主题漂移。
- 本地输出、上传、平台草稿、发布成功和真实用户效果分别记录，不互相冒充。
