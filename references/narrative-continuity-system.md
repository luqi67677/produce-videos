# 叙事冲突与连贯性系统

## 目标

开头要让观众立刻知道“为什么值得继续看”，中段要围绕同一个问题、阻力或差距推进，结尾要兑现开头承诺。这是叙事结构，不是为了刺激而制造假冲突。

## 开头两秒

面向信息流的短视频，默认在 0—2 秒内展示下列一种真实可证的内容：

- 结果：观众最后能得到什么；
- 反差：以前和现在、以为和实际有什么不同；
- 合法冲突：真实需求与现有做法之间的矛盾；
- 关键问题：一个具体、后续会被回答的问题；
- 操作证据：直接给出真实界面、产物或前后状态。

如果资料无法支持冲突，使用结果、问题或演示，不得把普通步骤写成失败、危机或行业灾难。开头文案与画面证据必须同时成立；只在字幕中写冲突，画面却是无关装饰，不算通过。

## 中段推进

每条视频只保留一条核心张力，并使用“起点 → 阻力 → 关键动作 → 可见证据 → 改变”推进。

- 教程：先给可见结果，再回到关键操作，每一步都必须改变界面状态。
- 产品解释：先展示真实问题，再展示产品改变了哪个动作，最后给结果证据。
- 知识讲解：从一个误解或具体问题进入，用图解或案例完成回答。
- 故事与情绪：冲突来自人物的真实愿望和阻力，不靠夸大事件。

每个镜头在 `shot-readiness.json` 中记录 `narrative_function` 与 `continuity`。镜头必须接住上一个状态，并留下下一个可继续的对象、动作、问题、方向或视觉锚点。

章节只是叙事分组，不能替代真实剪辑镜头。新项目把每个进入时间线的镜头写入 V2.6 `shots`，逐一绑定批准口播片段、画面职责和语义切点；同一章节拆成多个镜头时，所有片段拼接后必须完整、按顺序还原该段批准口播。

## A-roll 与 B-roll 的叙事接力

- A-roll 维持声音、人格或主对象连续；B-roll 只在需要证明、解释或遮盖必要跳切时进入。
- B-roll 必须填写 `covers`，并保留一个返回主轴的连续点。
- 人物出现在 A-roll、B-roll 或补充插画中时，都消费同一份已锁定人物档案，不允许因镜头角色不同而换人。

## 结尾兑现

结尾必须回答开头的结果、问题或冲突，并给出真实证据。行动引导必须与当前故事相关，不在故事结束后另外插入一段无关的通用口号。

## 叙事契约

从 `assets/story-contract-template.json` 生成 `story-contract.json`，与完整口播一起进入内容方向确认。它只保存本条视频的叙事逻辑，不保存平台进度或用户隐私。
